# Исправления по независимому ревью 10 октября 2026

База: снимок `31ee962ca1fb00454aeb9854de99cbb60757b3fa` с Mac.

## Изменения

- Grok/GLM observer сопоставляет текущий структурированный prompt и conversation ID, а не подстроку всей истории. Связь запроса передаётся серверу. Сервер отклоняет отсутствующую/несовпадающую связь и явно неверный conversation ID в ответе Grok.
- Для Grok поддержаны точные endpoints `new` и `/{id}/responses`, для GLM `chat_id`/`chatId` и текущая строка `message` или последнее пользовательское `messages[].content`. Неизвестная форма намеренно не принимается. Это требует отдельной проверки совместимости текущего сайта; реальные аккаунты при доработке не использовались.
- Non-stream HTTP disconnect отменяет работу в очереди и передаёт сигнал действующему worker. Уже отправленный неопределённый запрос не повторяется.
- Browser submit резервируется под lock, pacing проходит без глобального broker lock, затем владение перепроверяется. Двойной submit и navigation во время резервирования отклоняются. RPC submit ограничен оставшимся временем lease вместо фиксированных 10 секунд.
- Неверные DeepSeek continuation IDs отклоняются до обращения к аккаунту.
- Исторические tool calls валидируются до преобразования prompt. Повторяющиеся JSON-ключи в новых аргументах отвергаются.
- Все результаты пачки инструментов проверяются до захвата одноразового continuation cache.
- DeepSeek SSE отвергает error+[DONE] и новое содержимое после терминального события.
- Приватная запись больше не меняет права произвольного уже существующего родительского каталога. Новые файлы остаются 0600.
- Подсказки об автоматическом открытии браузера приведены к ручному входу.

## Развёртывание

Обновлять controller и observer совместно с сервером. Старый observer не передаёт новый request binding, и сервер правильно отклонит такие ответы. Не включать fallback к небезопасному substring matching ради совместимости.

Применение патча не обновляет приватные сгенерированные userscripts автоматически и не создаёт новую пару/токен. Их обновление и перезагрузка вкладки выполняются отдельно в обычном установленном процессе. Код сам не выполняет релиз, перезапуск или отправку сообщений модели.

## Проверки и ограничения

Новые регрессии: `tests/test_root_review_fixes.py`, `tests/observer_binding_fixture.cjs`, два браузерных сценария в `tests/test_userscripts.py`. Node fixture исполняет настоящий observer, не обращаясь в сеть.

Полный числовой итог и environment записываются в передаваемый `VALIDATION.json` после финального прогона. Обычные тесты не заменяют opt-in browser/Harness fixtures. Запуск Chromium в облачной среде упёрся в системное ограничение socket() EPERM, включая повтор с разрешённым повышением прав; браузерные сценарии здесь не квалифицированы. На Мак передаются исходники и тесты для отдельной проверки перед релизом.

Реальный WASM-модуль Wasmtime успешно создан в облачной среде. Настоящий challenge не решался. Живые модельные аккаунты, их квоты и текущие сайты не проверялись. Ограничения остальных HTTP-путей, capacity очереди и lock-файл зависимостей остаются отдельными архитектурными задачами. Дополнение ниже описывает ограничения SSE DeepSeek/Qwen.

## Дополнительное закрытие F03/F05/F08/F10/F12 на Mac

- DeepSeek и Qwen читают SSE через общий ограниченный reader: 300 секунд общего
  времени, 15 секунд ожидания одного чтения, 8 MiB ответа, 1 MiB строки.
  Отмена проверяется до/после чтения и перед успешным завершением. При молчащем
  соединении остановка ограничена read timeout; мгновенный отзыв удалённой
  генерации не гарантируется. Ошибки не запускают повторную отправку.
- Qwen отклоняет новые answer delta после завершения, противоречащие статусы
  завершения и повтор parent UUID. Вторичные кандидаты по-прежнему исключаются.
- Повтор идентичного финального snapshot DeepSeek допустим без повторного текста.
- Harness проверяет существующий owned default при каждом обновлении каталога;
  отсутствующая модель отклоняется до записи. Явный --default-model включает строку.
- PR #1 с алиасами моделей в эту серию не включён.

Эти изменения закрывают конкретные дефекты аудита, но не означают отсутствие
лимитов или риска блокировки аккаунта. Проверки используют только фикстуры.
